# AI Self-Healing Strategy

## Objective

Modern web applications frequently change element IDs, classes, and DOM structures, causing UI automation tests to fail because of outdated locators. An AI-assisted self-healing mechanism can reduce maintenance by automatically suggesting improved locators.

---

# 1. Detection

When a Playwright action fails because an element cannot be located, the framework should capture:

- Failed Playwright locator
- Exception message
- Current page URL
- Current DOM (page HTML)
- Screenshot of the failed page
- Timestamp and test name

This information provides enough context for an AI model to understand why the locator failed.

---

# 2. AI Prompt Strategy

The captured information is sent to an LLM with a structured prompt.

Example Prompt:

You are an automation testing assistant.

The following Playwright locator failed:

Locator:
#loanamount-old

Current Page HTML:
<DOM CONTENT>

Task:
1. Explain why the locator failed.
2. Suggest the best Playwright locator.
3. Suggest an alternative CSS selector.
4. Suggest an XPath locator.
5. Explain why the new locator is more reliable.

The AI should prefer stable locators such as:
- getByRole()
- getByLabel()
- getByPlaceholder()
- data-testid
- Stable CSS selectors

instead of dynamic IDs or autogenerated class names.

---

# 3. Validation Before Applying the Fix

The AI-generated locator should never be accepted automatically.

Before replacing the original locator, the framework should verify that:

- Exactly one matching element exists.
- The element is visible.
- The element is enabled.
- The intended Playwright action succeeds.
- The recovered locator consistently works across multiple executions.

If validation fails, the original test should remain failed for manual review.

---

# 4. Proposed Workflow

1. Test execution starts.
2. Locator fails.
3. Failure details are collected.
4. Current DOM is captured.
5. AI receives the failed locator and page HTML.
6. AI suggests improved locator(s).
7. Suggested locator is validated automatically.
8. If validation succeeds, the locator is used and logged.
9. Otherwise, the test fails and the suggestion is sent for manual review.

---

# 5. Proof of Concept

As a proof of concept, this project includes a helper method (`selfHealClick`) that demonstrates a basic fallback mechanism by attempting multiple locator strategies before reporting failure.

In a production implementation, these alternative locators would be generated dynamically by an AI model instead of being predefined.
